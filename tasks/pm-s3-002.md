## Title
Implement S3 API Gateway: Token Bucket Rate Limiting, Request Routing, and S1/S2 Response Aggregation

## Description
Build the core gateway logic: per-client rate limiting with token bucket algorithm, path-based routing to upstream services (S1, S2), and response aggregation with circuit breakers and caching.

## Acceptance Criteria
- [ ] Token bucket rate limiter: configurable capacity/refill, per-client (API key) and per-IP tiers
- [ ] Request router: path prefix → upstream service mapping, header forwarding, timeout configuration
- [ ] Response aggregator: fan-out to S1/S2, merge responses, handle partial failures
- [ ] Circuit breaker: failure threshold, timeout, half-open state, metrics emission
- [ ] Redis caching layer: TTL-based cache for aggregated responses, cache key strategy
- [ ] Health endpoints: `/health/live`, `/health/ready` with upstream dependency checks
- [ ] Metrics: request latency, error rate, cache hit rate, circuit breaker state (Prometheus)
- [ ] k6 load test: 1000 req/s sustained, p99 < 100ms, < 0.1% error rate

## Verification
- Unit tests: rate limiter correctness, circuit breaker state transitions
- Integration tests: mock S1/S2 upstreams, verify aggregation logic
- Load test: k6 script in CI, results compared to baselines
- Contract tests: S3→S4 API contracts verified via Pact

## Security Notes
- Rate limiting prevents abuse/DDoS
- Circuit breaker prevents cascade failures
- No sensitive data in logs (sanitize headers)
- CORS policy: S4 origin only
- Helmet-equivalent security headers (Fastify helmet)
