## Workload case for proposed hires

### ba-2 (Business Analyst)

**Why:** BA tasks are independent and can be parallelized to speed up upstream analysis, allowing DEV to start earlier. Currently, a single BA instance handled all 6 BA tasks sequentially. With the idea backlog containing 3 additional products (json-formatter, markdown-preview, qr-code-generator), a second BA instance will enable parallel analysis of multiple products, reducing the bottleneck before DEV work begins.

**Parallelization benefit:** Two BA instances can work on different products simultaneously, allowing DEV instances to start earlier on completed analysis. This aligns with §3.5.2 (detect parallelizable work) and §3.5.6 (builders first).

### dev-3 (Developer)

**Why:** DEV instances are overloaded. dev-2 is currently handling 4 tasks (daycalc, colorlab, loremipsum, uuid-generator) while dev-1 handles 1 task (diffcheck-fix). Adding a third DEV instance will parallelize the remaining product builds, speeding up delivery and reducing the load on dev-2.

**Parallelization benefit:** Three DEV instances can work on independent products simultaneously, each on its own branch, with TECHLEAD reviewing sequentially. This matches the portfolio rule §3.5.5 (multi-project concurrency) and the efficiency mandate §3.5.6 (shipped code first).
